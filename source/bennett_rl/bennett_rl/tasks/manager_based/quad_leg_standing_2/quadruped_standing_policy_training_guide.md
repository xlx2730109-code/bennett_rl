# 四足机器人纯站立策略训练指南

> 目标：训练一个四足机器人在平地上保持固定站姿，在受到轻微初始偏差、模型误差或外部推扰时，能够主动调整关节并恢复稳定。  
> 适用场景：Isaac Lab + RSL-RL，关节位置残差动作，真实机器人使用电机位置/速度反馈与 IMU。

---

## 1. 核心结论

纯站立任务不应该简单等同于“把行走任务的速度指令设为 0”。

更合理的做法是单独建立一个固定站姿任务，并删除以下行走相关内容：

- 速度指令跟踪
- 步态奖励
- 抬脚奖励
- 足端腾空时间奖励
- 摆动腿高度奖励
- 步频奖励
- 原地踏步相关机制

站立任务重点应该放在：

- 机身保持水平
- 机身保持目标高度
- 机身线速度接近 0
- 机身角速度接近 0
- 关节接近默认站姿
- 四个足端持续接触地面
- 足端尽量不滑动
- 动作平滑
- 电机力矩不过大
- 受到扰动后能够恢复

如果只要求无扰动情况下固定站立，普通关节位置 PD 控制通常已经能够完成。  
强化学习的主要价值是获得：

- 抗推扰能力
- 质量变化适应能力
- 质心偏移适应能力
- 地面摩擦变化适应能力
- 电机参数误差适应能力

---

## 2. 推荐控制形式

推荐让策略输出关节目标角度的残差，而不是直接输出电机力矩。

```python
q_des = q_default + action_scale * action
```

其中：

- `q_default`：标准站立关节角
- `action`：策略输出，通常限制在 `[-1, 1]`
- `action_scale`：动作缩放系数
- `q_des`：发送给关节 PD 控制器的目标角度

电机 PD 力矩形式：

```python
tau = kp * (q_des - q) - kd * joint_vel
```

第一版建议：

```python
action_scale = 0.20
```

即允许策略在默认站姿附近调整约：

```text
±0.20 rad ≈ ±11.5°
```

也可以按关节分别设置：

```text
髋外展关节：0.10 ～ 0.15 rad
髋俯仰关节：0.20 ～ 0.25 rad
膝关节：    0.20 ～ 0.30 rad
```

不建议一开始使用过大的动作范围，例如：

```python
action_scale = 0.5
```

否则容易出现：

- 腿部突然大幅摆动
- 高频抖动
- 瞬间输出峰值力矩
- 学出奇怪的蹲姿或趴姿
- 利用机械限位支撑身体

## 3. 观测维度设计

### 3.1 推荐的最小观测

设实际驱动电机数量为 `n`。

| 观测项 | 维度 | 真机来源 |
|---|---:|---|
| 机身角速度 | 3 | IMU 陀螺仪 |
| 投影重力方向 | 3 | IMU 姿态估计 |
| 驱动关节相对位置 | n | 电机编码器 |
| 驱动关节速度 | n | 电机反馈 |
| 上一步动作 | n | 控制器内部保存 |
| 总维度 | `6 + 3n` | |

如果有 8 个实际驱动电机：

```text
观测维度 = 3 + 3 + 8 + 8 + 8 = 30
动作维度 = 8
```

如果有 12 个实际驱动电机：

```text
观测维度 = 3 + 3 + 12 + 12 + 12 = 42
动作维度 = 12
```

推荐最小观测：

```python
base_ang_vel
projected_gravity
joint_pos_rel
joint_vel_rel
last_action
```

---

### 3.2 是否加入机身线速度

可以在仿真奖励函数中使用：

```python
base_lin_vel
```

但是第一版不建议直接输入 Actor，除非真机上有可靠的状态估计器。

原因：

- 仿真可以直接读取真实机身线速度
- 真机仅靠普通 IMU 很难长期稳定估计线速度
- 仿真使用真值、真机无法获得，会产生 sim-to-real 差距

建议：

```text
Actor 不输入 base_lin_vel
奖励函数可以使用 base_lin_vel
```

---

### 3.3 是否加入关节力矩

第一版不建议将关节力矩作为 Actor 观测。

原因：

- 真机力矩反馈可能存在偏差
- 力矩估计可能经过滤波
- 力矩反馈可能存在通信延迟
- 基础站立仅依靠 IMU、位置、速度即可完成

更合适的用途：

- 奖励函数中的力矩惩罚
- TensorBoard 监控
- 真机安全监控
- RMS 力矩统计
- 峰值力矩统计

---

### 3.4 是否加入足端接触

如果真机没有足端力传感器，不建议把足端接触输入 Actor。

可以在仿真中使用接触传感器来计算：

- 四足是否接触地面
- 足端是否滑动
- 机身是否碰地
- 大腿、小腿是否发生非法接触

但这些值可以只用于奖励和终止条件，不必输入 Actor。

---

## 4. Bennett 闭链机构特别注意事项

动作维度必须等于实际驱动电机数量，而不是 URDF 中所有关节数量。

例如：

```text
URDF 总关节数：12
真实驱动电机数：8
闭链被动关节数：4
```

则应该使用：

```text
动作维度：8
关节位置观测：8
关节速度观测：8
```

不要将以下状态直接输入 Actor：

- 真机没有编码器的被动关节角度
- 真机无法测量的闭链内部状态
- 仿真中直接获得、真机无法获得的理想值

这些状态可以：

- 不使用
- 仅输入 privileged critic
- 用于仿真调试和奖励计算

## 5. 默认站姿必须先验证

在开始 RL 训练前，先进行零动作测试：

```python
action[:] = 0
```

此时：

```python
q_des = q_default
```

让机器人依靠默认站姿和 PD 控制，在仿真中运行 10～20 秒。

需要记录：

```python
applied_torque
joint_pos
joint_vel
base_height
base_ang_vel
projected_gravity
contact_forces
```

统计：

- 平均力矩
- RMS 力矩
- 最大力矩
- 99% 分位力矩
- 机身高度误差
- 横滚和俯仰
- 足端滑动
- 是否有高频振荡

如果零动作状态下机器人都无法正常站立，优先排查：

- 默认关节角不合理
- 机身目标高度不合理
- 质心位置不合理
- 腿部力臂过大
- 电机额定力矩不足
- `kp`、`kd` 不合理
- 关节方向错误
- 闭链约束错误
- URDF 质量和惯量错误
- 接触参数错误
- 关节摩擦错误

不要先依赖奖励函数解决结构和参数问题。

## 6. 电机力矩限制

以 DM-J8006-2EC 为例，常见参数为：

```text
额定力矩：8 N·m
峰值力矩：20 N·m
```

峰值力矩不能理解为可以持续输出。

建议设置两级约束：

```python
hard_effort_limit = 20.0
soft_torque_limit = 8.0
```

含义：

- `hard_effort_limit`：绝对硬裁剪，任何情况下不能超过峰值
- `soft_torque_limit`：超过额定力矩后在奖励中明显惩罚

工程上建议：

```text
长期 RMS 力矩尽量低于 5～6 N·m
长期不要超过额定 8 N·m
瞬时峰值不要超过 20 N·m
```

5～6 N·m 是保守建议，用于给以下误差留余量：

- 温升
- 建模误差
- 地面冲击
- 电机参数误差
- 电流环误差
- 真机摩擦
- 通信延迟

## 7. 推荐奖励函数

纯站立任务建议保留以下奖励。

| 奖励项 | 初始权重建议 | 作用 |
|---|---:|---|
| 机身保持水平 | `+4.0` | 核心目标 |
| 保持目标高度 | `+2.0` | 防止趴下或蹲下 |
| XY 线速度接近 0 | `+1.5` | 防止位置漂移 |
| 机身角速度接近 0 | `+1.0` | 防止晃动和旋转 |
| 关节接近默认站姿 | `+1.0` | 避免奇怪姿态 |
| 四足保持接触 | `+0.5` | 防止原地踏步 |
| 存活奖励 | `+0.2` | 鼓励完成整个回合 |
| 足端滑动 | `-0.3 ～ -0.5` | 防止脚底滑动 |
| 动作变化率 | `-0.02` | 抑制动作抖动 |
| 关节速度 | `-0.005` | 降低关节运动 |
| 关节加速度 | `-2.5e-7` | 抑制高频振荡 |
| 关节力矩平方 | `-1e-5` | 降低能耗和过大力矩 |
| 非法身体接触 | `-2.0 ～ -5.0` | 防止机身、大腿碰地 |
| 摔倒终止惩罚 | `-5.0 ～ -10.0` | 明确失败状态 |

以上只是初始比例，需要根据训练曲线和实际表现调整。

---

## 8. 核心奖励实现示例

### 8.1 机身水平奖励

建议使用投影重力方向，不直接使用欧拉角。

```python
orientation_error = (
    projected_gravity[:, 0] ** 2
    + projected_gravity[:, 1] ** 2
)

reward_upright = torch.exp(
    -orientation_error / 0.12**2
)
```

目标：

```text
projected_gravity_x → 0
projected_gravity_y → 0
```

---

### 8.2 机身高度奖励

```python
height_error = base_height - target_height

reward_height = torch.exp(
    -(height_error ** 2) / 0.03**2
)
```

建议初始高度容差：

```text
0.03 ～ 0.05 m
```

高度奖励必须足够明显，否则策略可能通过趴下、蹲下或折叠腿部来减少力矩。

---

### 8.3 静止奖励

```python
lin_vel_error = (
    base_lin_vel[:, 0] ** 2
    + base_lin_vel[:, 1] ** 2
)

reward_zero_lin_vel = torch.exp(
    -lin_vel_error / 0.10**2
)

ang_vel_error = torch.sum(
    base_ang_vel ** 2,
    dim=1
)

reward_zero_ang_vel = torch.exp(
    -ang_vel_error / 0.25**2
)
```

---

### 8.4 关节姿态奖励

```python
joint_error = joint_pos - default_joint_pos

reward_joint_pose = torch.exp(
    -torch.mean(joint_error ** 2, dim=1) / 0.15**2
)
```

作用：

- 正常状态保持默认站姿
- 受到扰动时允许暂时调整
- 恢复后回到标准姿态

不要把该奖励设置得过大，否则策略会退化成僵硬的关节位置保持器。

---

### 8.5 力矩惩罚

```python
torque_penalty = torch.sum(
    applied_torque ** 2,
    dim=1
)
```

力矩惩罚权重不能过大。

如果过大，策略可能学会：

- 趴下
- 坐下
- 把关节顶到机械限位
- 利用碰撞支撑身体
- 牺牲姿态稳定来减少力矩

---

### 8.6 动作变化率惩罚

```python
action_rate_penalty = torch.sum(
    (action - last_action) ** 2,
    dim=1
)
```

作用：

- 减少动作突变
- 减少真机高频抖动
- 降低电流冲击
- 提高 sim-to-real 稳定性

但权重不能太大，否则策略受到推力后反应过慢。

---

## 9. 足端接触奖励

目标：

```text
四个脚持续接触地面
机身不接触地面
大腿不接触地面
小腿不发生异常碰撞
足端接触时尽量不滑动
```

可以定义：

```python
foot_contact = contact_force_z > contact_threshold
missing_contact = 4 - foot_contact.sum(dim=1)
```

惩罚：

```python
missing_contact_penalty = missing_contact.float()
```

不要强行要求四条腿垂直支撑力完全相等。

如果机器人质心偏前，正常情况可能是：

```text
前腿支撑力 > 后腿支撑力
```

只要满足整体平衡和稳定，不必追求四足受力完全一致。

## 10. 终止条件

建议设置以下终止条件：

- 机身碰地
- 大腿或其他禁止部位碰地
- 机身高度过低
- 横滚角过大
- 俯仰角过大
- 关节严重越限
- 回合时间到达上限

示例：

```python
base_height < 0.60 * target_height
abs(roll) > 0.75
abs(pitch) > 0.75
```

其中：

```text
0.75 rad ≈ 43°
```

不要一开始超过 10° 就终止，否则策略没有足够机会学习恢复。

推荐回合长度：

```python
episode_length_s = 20.0
```

## 11. 推荐训练课程

### 第一阶段：学习正常站立

配置：

```text
平地
无外部推扰
无质量随机化
无质心随机化
无摩擦随机化
无动作延迟
无观测噪声
初始状态接近默认站姿
```

初始随机范围建议：

```text
关节角偏差：±0.05 rad
横滚：      ±5°
俯仰：      ±5°
机身角速度：很小
```

目标：

- 持续站立 20 秒
- 不原地踏步
- 不持续滑动
- 不高频抖动
- 高度基本稳定

---

### 第二阶段：增加初始状态误差

```text
关节角偏差：±0.10 rad
横滚：      ±10°
俯仰：      ±10°
机身角速度：±0.2 ～ 0.3 rad/s
```

目标：

- 从轻微姿态偏差中恢复
- 从关节初始误差中恢复
- 恢复到默认站姿附近

---

### 第三阶段：加入 sim-to-real 随机化

建议逐步加入：

```text
机身质量：        ±5% ～ 10%
质心 X/Y：        ±1 ～ 2 cm
地面摩擦：        0.6 ～ 1.2
电机力矩强度：    0.9 ～ 1.1
Kp、Kd：          ±10%
动作延迟：        0 ～ 1 个策略周期
关节位置噪声：    ±0.01 ～ 0.03 rad
关节速度噪声：    ±0.2 ～ 0.5 rad/s
IMU 角速度噪声：  ±0.05 ～ 0.1 rad/s
```

不要一次性加入全部强随机化，否则训练可能直接失败。

---

### 第四阶段：加入推扰恢复

初始推扰建议：

```text
每 8 ～ 12 秒施加一次
XY 方向速度扰动：±0.1 ～ 0.2 m/s
```

策略稳定后可增加到：

```text
±0.3 ～ 0.5 m/s
```

如果要求足端完全不移动，推力过大后从物理上就无法恢复。

当质心投影超出支撑多边形时，机器人通常必须：

- 迈步
- 调整足端
- 或摔倒

因此应明确任务目标：

```text
固定足端小扰动恢复
```

还是：

```text
允许迈步的大扰动恢复
```

纯站立任务一般属于前者。

## 12. 推荐观测配置示例

```python
@configclass
class PolicyCfg(ObsGroup):
    base_ang_vel = ObsTerm(
        func=mdp.base_ang_vel,
        noise=Unoise(
            n_min=-0.1,
            n_max=0.1,
        ),
    )

    projected_gravity = ObsTerm(
        func=mdp.projected_gravity,
        noise=Unoise(
            n_min=-0.03,
            n_max=0.03,
        ),
    )

    joint_pos = ObsTerm(
        func=mdp.joint_pos_rel,
        params={
            "asset_cfg": SceneEntityCfg(
                "robot",
                joint_names=ACTUATED_JOINT_NAMES,
            )
        },
        noise=Unoise(
            n_min=-0.02,
            n_max=0.02,
        ),
    )

    joint_vel = ObsTerm(
        func=mdp.joint_vel_rel,
        params={
            "asset_cfg": SceneEntityCfg(
                "robot",
                joint_names=ACTUATED_JOINT_NAMES,
            )
        },
        noise=Unoise(
            n_min=-0.3,
            n_max=0.3,
        ),
    )

    actions = ObsTerm(
        func=mdp.last_action
    )

    def __post_init__(self):
        self.enable_corruption = True
        self.concatenate_terms = True
```

第一版建议删除：

```python
velocity_commands
height_scan
base_lin_vel
```

原因：

- 固定站立不需要速度指令
- 平地任务不需要高度扫描
- 真机可能没有可靠机身线速度估计

## 13. 推荐动作配置

伪代码：

```python
@configclass
class ActionsCfg:
    joint_pos = mdp.JointPositionActionCfg(
        asset_name="robot",
        joint_names=ACTUATED_JOINT_NAMES,
        scale=0.20,
        use_default_offset=True,
        preserve_order=True,
    )
```

要求：

```text
ACTUATED_JOINT_NAMES 只包含真实驱动关节
顺序必须与真机电机顺序一致
默认关节角必须与最终真机站姿一致
```

需要明确检查：

- 仿真关节正方向
- 真机电机正方向
- 电机 ID 顺序
- 策略动作顺序
- 编码器零位
- 默认关节角
- 减速比
- 力矩方向

## 14. 推荐训练参数

结合：

```python
sim.dt = 0.005
decimation = 4
```

则：

```text
仿真频率：200 Hz
策略频率：50 Hz
策略周期：20 ms
```

第一版建议：

```python
episode_length_s = 20.0
action_scale = 0.20
```

PPO 其他参数可暂时沿用现有行走任务配置，但建议重点观察：

- 学习率是否过大
- entropy 是否导致站立时动作持续抖动
- policy std 是否长期过大
- value loss 是否异常
- episode length 是否很快到达上限

## 16. 推荐验收标准

无推扰条件下：

```text
20 秒站立成功率 > 95%
Roll/Pitch RMS < 2° ～ 3°
XY 线速度 RMS < 0.03 ～ 0.05 m/s
足端无持续滑动
关节无肉眼可见高频振荡
长期 RMS 力矩低于额定力矩
无机身、大腿非法接触
```

推扰条件下：

- 能恢复到目标高度
- 能恢复到水平姿态
- 关节最终回到默认站姿附近
- 恢复时间合理
- 不出现持续振荡
- 不持续使用峰值力矩

## 17. 常见错误

### 17.1 速度指令设为 0，但仍保留步态奖励

结果：

```text
机器人原地踏步
```

### 17.2 只奖励机身水平

结果：

```text
机器人趴着也能保持机身水平
```

必须同时加入：

- 高度奖励
- 非法接触惩罚
- 默认关节姿态奖励
- 四足接触约束

### 17.3 力矩惩罚过大

结果：

- 趴下
- 坐下
- 使用机械限位
- 放弃主动恢复

### 17.4 默认关节姿态奖励过大

结果：

- 策略过度僵硬
- 受到推力后不会主动调整
- 实际上退化成普通 PD 控制

### 17.5 动作变化惩罚过大

结果：

- 动作平滑
- 但恢复速度太慢

### 17.6 动作变化惩罚过小

结果：

- 策略高频正负切换
- 真机电机抖动
- 电流冲击大
- sim-to-real 失败

### 17.7 仿真允许峰值力矩长期输出

结果：

- 仿真很稳定
- 真机过流
- 真机过热
- 电机掉使能
- 电源保护

### 17.8 Actor 使用真机不存在的观测

例如：

- 仿真真实机身线速度
- 被动关节真实角度
- 真实足端接触力
- 地面摩擦系数
- 仿真中直接读取的质心位置

结果：

```text
仿真效果很好，但真机无法部署
```
